# 等保对照（GB/T 22239-2019）

按《信息安全技术 网络安全等级保护基本要求》，对照代码与配置里**可静态发现**的等保项。

## 一、重要前提（先看这个）

**本工具不是等保测评，也不能替代测评。**

等保的绝大部分要求针对的是**已部署的系统与运维过程** —— 物理环境、边界设备、
安全管理中心、制度、人员。这些**代码扫描看不到**。

本工具只做一件事：**在代码和配置里，把「测评前开发者自己能改掉」的问题找出来。**

这样做的价值：测评时被指出的一堆问题，其实**上线前就能修**。

## 二、它查什么

| 级别 | 项 | 依据（章节名）|
|---|---|---|
| 🔴 高 | **默认口令**（admin/123456 等）| 安全计算环境 · 身份鉴别 / 访问控制 |
| 🔴 高 | **用 MD5/SHA1 处理口令** | 安全计算环境 · 数据保密性 |
| 🟡 中 | **明文传输**（http:// 端点）| 安全通信网络 · 通信传输 |
| 🟡 中 | **调试开关残留**（DEBUG=true）| 安全计算环境 · 入侵防范 |
| 🟡 中 | **错误信息泄露内部细节** | 安全计算环境 · 入侵防范 |

对应 GB/T 22239-2019 的 **6 个维度**中的 2 个：
安全通信网络 · 安全计算环境。
（另 4 个：安全物理环境 · 安全区域边界 · 安全管理中心 · 安全管理体系 —— 静态扫描覆盖不到）

## 三、为什么 source 只写章节名不写编号

**因为编号我无法逐条核实，编了就是假判据。**

标准里「安全计算环境 · 身份鉴别」「安全通信网络 · 通信传输」这些**章节名**是确定的，
你可以拿着自己手上的标准原文直接对照。写一个我核不准的 `8.x.4.y` 反而是误导。

**CI 里有卡口**：规则里出现 `数字.数字.数字` 形式的条款编号，测试直接失败。

## 四、怎么用

```bash
<cli 路径>                 # 扫当前目录
<cli 路径> --demo          # 看检出效果
<cli 路径> --list-rules    # 列出规则和依据
<cli 路径> --html r.html   # HTML 报告（给安全负责人看）
```

**退出码 1 = 有高危命中**。

## 五、边界（务必读）

- ❌ **不能替代等保测评**，也不保证通过测评。
- ❌ **不覆盖**物理环境、区域边界、安全管理中心、制度/人员/建设/运维管理。
- ❌ **不做缺项判定**：「没扫到问题」≠「该项符合」。
  例如「应启用多因素认证」——扫描器无法知道你的系统有没有开 MFA。
- ⚠️ **条款锚点是章节名，不是编号**：请以你手上的标准原文为准。
- ⚠️ 定为「第三级」的常见要求，但**具体要求随级别不同**，请对照你所定级别。
- 与配套插件的关系：日志留存（≥6 个月）单独在 `dsh-cn-log-retention` 里做。

## 六、覆盖面

5 项，覆盖代码/配置层面可静态发现的等保问题。
**不覆盖**：需要运行时观察的（MFA 是否启用、审计是否真在记录）、
需要看架构的（区域划分、边界设备）、需要看管理的（制度/人员）。
